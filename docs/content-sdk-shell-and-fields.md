# Native shell and editable primitives — ticket 05

The navigation shell and `nextjs-sxa` primitive folders now import Content SDK directly. They no longer depend on the JSS-shaped compatibility import or global JSX annotation bridge. Unported feature components still retain those temporary bridges until their migration/contract gates complete.

## Preserved contracts

- Root `headless-header`, `headless-main` and `headless-footer` slots and `jss-header-content` remain unchanged.
- Container, row/column and partial-design rendering names/signatures remain unchanged. Row/column splitters request the concrete `DynamicPlaceholderId` instance. The SDK resolves wildcard definition data and keeps its raw names in metadata editing; fixtures exercise both concrete and wildcard payload shapes.
- Existing component wrapper classes, IDs, layout variants and field/media URLs are retained.
- Custom `EventInfo` title data and `Languages` stay under `page.layout.sitecore.context`. Route body fallback reads `page.layout.sitecore.route`; neither is flattened into an invented normalized Page property.
- `Page.locale` and `Page.mode` drive language and normal/edit/preview behavior.
- Field helpers use native Text/RichText/Image/Link contracts and preserve metadata field identity. Banner image editing no longer rewrites legacy editable HTML.
- Header CMS links use the SDK Link helper so field metadata is not discarded.
- No Sitecore items, schema, saved presentation IDs or external integration providers were changed.

## Observed regressions fixed

Each was checked through the running rendering host and retained red/green evidence:

1. Missing optional language context no longer throws; only the current locale is offered when availability information is absent. This does not imply other translations exist.
2. Deleted image/banner datasource no longer breaks author rendering.
3. Deleted footer logo/empty link title no longer breaks the shell.
4. Nested row/column instance slots resolve correctly through partial designs; absent optional styles are safe.
5. Header link metadata survives editing rather than disappearing behind a plain Next Link.
6. Missing breadcrumb fields are safe in normal/edit/preview rendering.
7. Empty banner `src` no longer becomes an invalid string `style` prop; its empty image remains metadata-editable.
8. Deleted main-navigation logo item does not remove the usable ticket navigation.
